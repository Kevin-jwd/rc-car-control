# RC카 로컬 코드 확인 결과

확인일: 2026-11-08

## 결론

`07.AUTO_CAR/`는 발표자료에 대응하는 ATmega128A RC카 코드다. 이전 GitHub branch_1의 비어 있던 자율주행 함수와 달리, 자율·수동 주행·칼만 필터·FND 표시·6개 모드 전환 구현을 포함한다. 이후 기술서와 구조도는 이 로컬 소스를 우선 근거로 사용한다.

다만 정적 검토에서 아래 오류가 확인되어 ‘모든 기능이 정상 검증된 최종본’이라고 단정하지 않는다. 소스는 수정하지 않았다. 현재 환경에서 AVR 컴파일러를 명령 경로로 찾지 못해 재빌드하지 않았고, 실제 차량 구동·영상 검증도 수행하지 않았다. Debug의 hex·elf·lss 등 산출물 존재만으로 현재 소스와 동일한 빌드·동작을 보증하지 않는다.

## 발표와 대응하는 핵심 구현

- main.c 103~135행: 수동 → 자동 → 시간 조회 → 후진·좌회전·우회전 통계 조회, 버튼으로 6개 모드 순환.
- main.c manual_mode(): F/B/L/R/S 명령과 대소문자를 처리하여 모터·표시 함수 호출.
- ultrasonic.c: 센서별 상태를 유지하는 칼만 필터. Q=0.5, R=5.0. 60ms 조건마다 센서를 순환 트리거하므로 설계상 개별 센서는 약 180ms 주기로 요청되며, 이는 실측 성능 수치가 아니다.
- main.c auto_mode(): 가까운 장애물 후진 우선 처리, 전방 거리·거리 변화 기반 회전, 좌우 거리 및 변화량의 가중합으로 조향.
- pwm.c: 좌우 출력 OCR1A/OCR1B와 방향 핀을 이용한 제어.
- fnd.c: 방향 애니메이션·주행 시간·동작 통계 표시 코드 존재. 표시값 정확성은 아래 문제와 구분한다.

## 코드에서 확인한 문제와 제한

### 1. 주행 시간 환산식

main.c 288행은 `lap_time = min_count + 60 * sec_count;`다. 분·초를 총 초로 변환하려면 `60 * min_count + sec_count`가 되어야 한다. 예를 들어 1분 2초가 현재 식으로 121이 되어 의도한 62초와 다르다. 이를 정확한 주행 시간 계측 성과로 쓰지 않는다.

### 2. 동작 횟수 집계

- `backward_cnt`는 초기화·표시만 있고 증가 코드가 없어 후진 횟수를 집계하지 못한다.
- 좌·우회전 카운터는 회전 상태 진입 시점이 아니라 auto_mode 실행 때마다 증가한다. 전방 회피와 아래 가중 조향이 한 호출에 모두 실행되면 두 번 증가할 수도 있다.
- FND에서 카운터를 20으로 나누지만 일정 시간·상태 전이와 연결된 실제 동작 횟수라는 근거는 없다.
- fnd.c 471·528·584행의 `numbers[cnt / 20 % 100]` 형태는 10칸 배열에 최대 99 인덱스를 만들 수 있다. 해당 카운터가 200 이상이면 범위를 벗어날 수 있다.

따라서 ‘통계 조회 화면 구현’은 확인되지만 ‘정확한 누적 동작 횟수 검증’은 확인되지 않는다.

### 3. 전방 회피 명령이 후속 조향에 의해 덮어써질 수 있음

main.c 216행의 전방 장애물 회피 후에도 234행 이하 가중 조향이 실행된다. 같은 호출에서 앞서 선택한 좌·우회전 명령이 다시 바뀔 수 있다. 특히 좌우 거리·변화가 같으면 가중값이 0이 되어 마지막 forward가 선택될 수 있다. 분기 우선순위 점검이 필요하다.

### 4. 포트 전체 쓰기와 핀 공유

fnd.h에서 FND1 자리 선택은 PORTF 상위 비트, FND2는 PORTA 상위 비트를 사용한다. 모터 방향은 PORTF 하위 비트, 초음파 Trigger는 PORTA 하위 비트다. 그런데 fnd.c의 `FND1_CONTROL_PORT = ...`, `FND2_CONTROL_PORT = ...`는 포트 전체에 값을 써서 하위 비트에도 영향을 준다. 모터 방향·Trigger 보존 여부를 점검해야 한다. 이는 소스의 포트 쓰기 경로를 확인한 것이며 실제 파형·구동 증상은 측정하지 않았다.

## 후진 문제의 현재 상태

발표 15쪽의 ‘후진 이후 if문 때문에 동작이 바뀔 수 있음’과 관련하여, 로컬 main.c 207~212행에는 후진·표시 후 즉시 `return`하는 코드가 있다. **auto_mode 내부에서 뒤의 조건문이 후진 명령을 덮어쓰는 경로는 차단되어 있다.** 다만 수정 시점·실제 후진 동작 성공 여부는 이 소스만으로 확인되지 않으며, 위 포트 공유 문제도 별도로 남는다.

## 기술서에 사용할 수 있는 표현

- ATmega128A 기반 초음파 센서 자율주행·Bluetooth 수동 제어 프로그램 구현
- 센서별 칼만 필터와 거리·거리 변화량을 이용한 조향 로직 구현
- 함수 포인터와 상태 변수로 주행·조회 모드를 분리
- Timer1 PWM 모터 제어 및 FND 상태·시간·통계 조회 화면 구성
- 개선 과제: 제어 분기 우선순위, 시간 환산·통계 집계 정확성, 공유 GPIO 포트의 비트 보존

‘거리 변화량’을 고정 주기로 정규화한 실제 속도로 표현하지 않는다. main은 센서 갱신과 독립적으로 반복되므로 거리 변화량과 샘플 시점의 관계도 향후 확인 대상이다.

## 그림 제작 근거

1. 시스템 구성도: HC-SR04 초음파 3개 / ZS-040 Bluetooth 모듈(UART) / 버튼 → ATmega128A(거리 필터·모드·주행 판단) → L298N 모터 드라이버(PWM·GPIO) → DC 모터. FND·상태 LED는 MCU의 별도 출력으로 표시한다.
2. 핵심 구현 그림: 센서 측정 → 칼만 필터 → 근접 장애물 후진 → 전방 회피·좌우 가중 조향. 현재 두 회전 분기는 순차 실행되므로 서로 배타적인 완성 로직으로 그리지 않는다.
